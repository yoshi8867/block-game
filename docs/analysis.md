### ⚠️ 영상에 등장하지 않은 4종 — 색상은 **추정치**
아래 4종은 260개 트레이 상태 전수 조사에서 **한 번도 관측되지 않았다.**
같은 계열의 나머지 회전이므로 존재는 거의 확실하지만, 색상은 검증된 값이 아니다.
원작 자료가 추가로 생기면 반드시 대조할 것.
관측된 계열이 전부 "4회전 = 4색 하나씩"이었으므로 남은 색을 추정치로 적는다.

| 모양 | 추정 색 | 근거 |
|---|---|---|
| `X. / XX` | pink | 3칸 L 계열 중 yellow·purple 사용됨, 초기 판정에서 pink로 관측됨 |
| `XX / X.` | cyan | 3칸 L 계열 남은 색 |
| `.X / XX / X.` | purple | S/Z 계열 중 yellow·pink·cyan 사용됨 |
| `XX / .X / .X` | pink | L 세로 계열 중 purple·cyan·yellow 사용됨 |

### 등장하지 않는 모양

## 5. 타이머

- 게이지는 오른쪽 끝부터 왼쪽으로 줄어든다. 감소는 **완전한 선형**
- 영상의 플레이 구간: 3.5초(`GO!` 종료) ~ 95초 → 실측 약 92초. **채택값은 95초**
- 원작에는 점수 임계점마다 시간을 더 주는 `time bonus`가 있었으나 **채용하지 않는다**
  → 보너스가 이미 다 반영된 상태로 보고, 게이지가 95초에 걸쳐 0까지 선형 감소

### 잔여 시간 경고 — 화면 전체 비네트 (96.7초 ~ 종료)

시계·게이지만 깜빡이는 게 아니다. **화면 전체를 덮는 흰 비네트가 숨쉬듯 밝아졌다
어두워진다.** 시계·게이지가 깜빡이는 것처럼 보인 건 비네트의 위쪽 끝이 가장 밝기
때문이었다. 피크/최저 프레임을 차분해 알파를 픽셀 단위로 실측했다.

| | 실측값 (1080×2340 기준) |
|---|---|
| 투명한 중앙 타원 | 반지름 480 × 545px (세로로 조금 김) |
| 타원 중심 | (540, 1105) = 50%, 47.2% |
| 화면 끝 알파 | **0.55** |
| 주기 | **2.2초** (최저→최저 4회 평균 2.17초) |
| 파형 | 오르내림 대칭, 상승 ~1.05초 / 하강 ~1.05초 |

> 구현은 시야를 가려서 타원을 1.27배로 넓히고 끝 알파를 0.36 으로 낮췄다 (사용자 지시).

### 게임 종료 화면 (t=103.60 ~ 녹화 끝)

빨간 `GAME OVER` 가 나타나는 시각을 프레임 단위로 찾은 결과 **103.60초**다.
그 뒤로 화면이 안 바뀐다.

- 화면을 **어둡게 덮지 않는다.** 경고 비네트가 호흡을 멈추고
  최대치의 **65%** 정도에서 밝은 채로 정지한다
- 보드·트레이·`block change` 가 전부 그대로 보인다
- `GAME OVER` 는 **보드 중앙이 아니라 화면 정중앙**에 온다 — 실측 중심 (546, 1160)
  = 50.6%, 49.6%. 폭은 화면의 약 61%
- 짙은 자주빛 빨강(#901030 계열)에 더 어두운 외곽선. 위쪽에 회색 광택 점
- **글자가 타일보다 아래에 깔린다.** 보드에 놓인 블록이 글자를 가린다
- `RETRY` 는 없다 (녹화가 1.1초 뒤 끊겨서 안 나왔을 수도 있다)

> 워드아트를 잘라내려 했으나 마지막 판의 블록이 `GAME` 을 가려서 온전한 글자를
> 얻을 수 없었다. 구현은 CSS 텍스트로 위치·크기·색·타일 아래 배치만 맞췄다.

### time bonus 연출 (실제 시간 추가 없음)
- 점수가 **6,000** 을 넘는 순간, **9,000** 을 넘는 순간 각각 1회 효과음 재생
- 사운드 파일은 사용자가 준비
- 게이지는 건드리지 않는다

## 9. 줄 삭제 애니메이션

30fps 기준 **2프레임 (약 67ms)** 의 매우 짧은 연출.

1. 줄이 완성되면 타일 본체가 즉시 사라진다
2. 각 칸 자리에서 **다이아몬드/꽃잎 모양 파편 약 8개가 방사형으로 튀어나간다**
3. 파편은 바깥으로 이동하면서 작아지고 투명해진다
4. 파편 색은 그 칸의 타일 색을 따른다 (노란 칸 → 금색 파편, 보라 칸 → 연보라·분홍 파편)

이미지 시퀀스로 쓸 만큼 프레임이 길지 않으므로 CSS/캔버스 파티클로 재현하는 편이 낫다.
1프레임째에 이미 한 칸 너비로 벌어진 로제트 형태이고, 2프레임째엔 칸 밖으로 날아가며
작아지고 흐려진다. 60Hz 화면에서 보이도록 구현은 160ms 로 늘렸다.

### NICE! / PERFECT! 배너 — 전수 측정

영상 전체에서 배너 32회를 검출해 매번 같은 수치가 나왔다.

| | 값 (1080×2340 기준) | 비율 |
|---|---|---|
| 중심 | x 541, y 463.5 | 50%, 19.81% |
| `PERFECT!` 크기 | 792 × 143 | 폭 73.3% |
| `NICE!` 크기 | 412 × 111 | 폭 38.1% |
| 표시 시간 | **0.60초** (예외 없음) | |

- **위치는 항상 고정이다.** 지워진 줄이 어디였든 보드 **첫 줄 높이**에 뜬다
- 등장할 때 **0.85배 → 1.0배**로 커진다 (약 0.27초, 1% 정도 오버슈트 후 정착)
- 사라질 때는 **페이드가 없다.** 한 프레임 만에 없어진다
- 무지개색 버블 레터 + 두꺼운 흰 외곽선. 폰트가 아니라 워드아트 이미지다.
  `tools/banner_crop.py` 로 알파까지 잘라내 `assets/banner_{nice,perfect}.png` 로 쓴다

## 10. UI 디테일

- **점수**: 어두운 라운드 알약 + 원형 `h` 코인 아이콘 + 흰색 굵은 산세리프 숫자
- **타이머**: 원형 시계 아이콘 + 보라 스타디움 게이지 (양 끝 완전 라운드)
- **NICE! / PERFECT!**: 9절 참조 (위치·크기·시간 전수 측정)
- **점수 표기**: 천 단위 구분 기호 **없음** (`4840`, `18375`, `32225` 로 실측)
- **트레이**: 라운드 사각 패널 3개, 얇은 보라 테두리. 블록은 패널 정중앙 정렬
- **block change**: 흰 알약 버튼, 하늘→보라 그라디언트 테두리 + 그라디언트 텍스트
- **배경**: 보라 우주 일러스트 (행성·별·하단 도시 실루엣). 게임플레이 영상만으로는
  UI에 가려지지 않은 깨끗한 배경 원본을 복원할 수 없다 → 별도 준비 필요
